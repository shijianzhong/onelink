# OneLink M2 实施计划（一对一聊天消息）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 M1（发现 + 设备列表 + 优雅退出）之上加一对一文字聊天：点设备行打开右侧聊天面板，输入发送后经 iroh QUIC 双向流送达对端，对端 UI 实时显示；对端不可达时给出失败提示而不是卡住 UI。

**Architecture:** 沿用 M1 的单向数据流：UI 只读模型快照、网络线程独占 endpoint。新增两条通道——**上行命令**（UI → 服务线程，`tokio::sync::mpsc::UnboundedSender<Command>`，同步 send 不阻塞 UI）与**下行事件**（沿用 M1 的 `EventQueue`，新增 `ChatReceived` / `ChatDelivered` / `ChatFailed`）。协议复用 M1 的握手流格式，把 `HelloMsg` 扩成 `Frame` 枚举（`Hello`/`HelloAck`/`Chat`/`ChatAck`），一条 QUIC 双向流承载一条 frame，线格式与 M1 完全兼容。

**Tech Stack:** iroh 1.4.1（`open_bi`/`accept_bi`/`read_to_end`）、gpui-kit 0.7（`component::input::{Input, InputState}`）、tokio（mpsc）、serde_json、tracing、anyhow

**Spec:** `../../LanLink-设计方案.md`（OneLink 定稿，v0.1 2026-11-04）；M1 计划 `2026-11-04-onelink-m1.md`

## Global Constraints

- 平台 macOS / Windows / Linux；Rust edition 2024；nightly 工具链（`rust-toolchain.toml` 已锁）
- ALPN 固定 `onelink-v1`；mDNS 服务名固定 `onelink-v1`
- 端到端加密不得关闭（iroh 默认）；M2 不配置 relay 策略
- UI 线程绝不阻塞等待网络：发送走命令通道，事件走 300ms 事件泵
- 单条 frame 上限 64KB（`MAX_FRAME_BYTES`），超限拒绝不截断
- 日志统一 `tracing`；错误统一 `anyhow`；每个任务一次 commit
- 现有 18 个测试必须保持全绿；`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings` 保持干净

## Review Focus

M2 的测试不覆盖但真实使用一定会撞上的情形（每条都要在对应任务的测试里钉住）：

1. **对端进程已退出时发送**：`open_bi` 或等 ACK 会超时/失败 —— 必须变成 `ChatFailed` 事件 + 面板提示，UI 不能卡住（Task 3 用「先关对端 endpoint 再发」的测试）。
2. **超长输入**：粘贴 100KB 文本发送 —— 本地拒绝并在面板提示，不得 panic 或发出半截消息（Task 1 decode/encode 上限 + Task 6 发送前校验）。
3. **畸形 frame**：局域网里非 OneLink 的 iroh 客户端乱发字节 —— 服务端 `read_frame` 失败只记日志、关流，进程不 panic（Task 1/Task 2）。
4. **消息归属串会话**：A 选中 B 时收到 C 的消息 —— 只进 C 会话并给 C 行加未读数，不能显示在 B 面板（Task 4/Task 6）。
5. **重复点击/连发**：快速连点发送按钮 —— 每次点击消息 id 唯一、顺序与本地显示一致（Task 4 测试 + Task 5 空输入不触发）。

```rust
use std::sync::Arc;
use std::time::Duration;
use onelink::net::{ALPN, EventQueue, EVENT_QUEUE_CAPACITY, UiEvent, serve_frames};
use onelink::proto::{Frame, MAX_FRAME_BYTES, decode_frame, encode_frame};
use iroh::endpoint::presets;

#[tokio::test]
async fn chat_frame_reaches_event_queue_and_gets_ack() {
    // 端点构造沿用 tests/handshake.rs 的做法（builder(presets::N0).alpns(...).bind()）
    let a = iroh::Endpoint::builder(presets::N0).alpns(vec![ALPN.to_vec()]).bind().await.unwrap();
    let b = iroh::Endpoint::builder(presets::N0).alpns(vec![ALPN.to_vec()]).bind().await.unwrap();
    let queue = EventQueue::new(EVENT_QUEUE_CAPACITY);
    let q = Arc::clone(&queue);
    let a_serve = a.clone();
    tokio::spawn(async move { serve_frames(&a_serve, "A", &q).await.unwrap() });

    let conn = b.connect(a.addr(), ALPN).await.unwrap();
    let (mut send, mut recv) = conn.open_bi().await.unwrap();
    let f = Frame::Chat { id: 42, text: "hi".into(), sent_at_ms: 1 };
    send.write_all(&encode_frame(&f).unwrap()).await.unwrap();
    send.shutdown().await.unwrap();
    let ack = decode_frame(&recv.read_to_end(MAX_FRAME_BYTES).await.unwrap(), MAX_FRAME_BYTES).unwrap();
    assert_eq!(ack, Frame::ChatAck { id: 42 });

    let mut got = None;
    for _ in 0..50 {
        if let Some(UiEvent::ChatReceived { node_id, id, text, sent_at_ms }) = queue.try_recv() {
            got = Some((node_id, id, text, sent_at_ms));
            break;
        }
        tokio::time::sleep(Duration::from_millis(50)).await;
    }
    let (node_id, id, text, _) = got.expect("no ChatReceived event");
    assert_eq!(node_id, b.id().to_string());
    assert_eq!((id, text.as_str()), (42, "hi"));
}
```

- [ ] **Step 3: 实现分发**

`dispatch_connection`：`conn.accept_bi().await` 拿 `(send, recv)` → `read_frame` → match：

- `Frame::Hello { name }`：回 `Frame::HelloAck { name: our_name }`（复用 `answer_hello` 的语义），然后 `conn.closed().await`（M1 教训：回完必须等对端关闭，否则拆链丢 ACK）
- `Frame::Chat { id, text, sent_at_ms }`：`push_event(queue, UiEvent::ChatReceived { node_id: conn.remote_id().to_string(), id, text, sent_at_ms })`，回 `Frame::ChatAck { id }`，再 `conn.closed().await`
- 其他（`HelloAck`/`ChatAck`）：只记 `warn!` 后关闭
- `read_frame` 出错：`warn!` 日志 + 关闭，不向上传播（非 OneLink 客户端乱发）

`serve_frames`：`while let Ok(incoming) = endpoint.accept().await` → 每个连接 `tokio::spawn(dispatch_connection(...))`；`spawn_iroh_service` 里把 `serve_handshake` 的调用点换成 `serve_frames(..., &service_queue)`。

# OneLink M1 实施计划（骨架 + 设备发现）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 OneLink 的 M1 里程碑——一个可运行的 GPUI 窗口程序，启动后通过 mDNS 自动发现同网段设备，经握手交换设备名，在左侧列表展示设备（在线/离线状态、设备名、node id），两台机器同网段运行即可互见。

**Architecture:** GPUI 主线程负责渲染，iroh 服务运行在独立 tokio runtime（后台线程），两者通过有界 channel 桥接（网络事件 → UI 事件队列 → `cx.notify()` 唤醒）。设备注册表（纯逻辑、无 I/O）是 UI 的唯一数据源，每次重绘前从注册表快照渲染，单向数据流。

**Tech Stack:** iroh（endpoint + mDNS 发现）、gpui-kit 0.7（GPUI + gpui-base + gpui-component）、tokio、serde/serde_json、tracing + tracing-subscriber、anyhow、gethostname

**Spec:** `../../LanLink-设计方案.md`（OneLink 定稿，v0.1 2026-11-04）

## 后续里程碑（不在本计划内，M1 完成后单独出计划）

- **M2 聊天**：一对一连接复用、消息信封（chat/ack）、✓/✓✓、未读计数
- **M3 文件传输**：blobs offer→确认→进度→校验、拖拽发送
- **M4 完整版增强**：SQLite 历史、断点续传、传输队列、设置页
- **M5 三平台打包**：GitHub Actions 自动构建

## Global Constraints

- 平台：macOS / Windows / Linux 三平台；Rust edition 2021；包名 `onelink`，产品名 OneLink
- 全 Rust 单二进制，无 Electron/重量级运行时
- ALPN 固定为 `onelink-v1`：连接建立时用 ALPN 过滤，只有 OneLink 端点能握手成功；mDNS 发现的非 OneLink iroh 端点会被拒绝（这是协议约束不是 bug）
- 端到端加密不得关闭（iroh 默认行为）；M1 不配置 relay 策略，用 iroh 默认
- UI 层只使用 gpui-kit 成熟组件，不自造样式；UI 线程绝不阻塞等待网络
- 日志统一 `tracing`；错误统一 `anyhow`
- 每次任务结束提交一次 git commit（本计划首个任务初始化 git 仓库）

## Review Focus

1. **重复发现**：同一设备被 mDNS 重复广播/重复握手 → 注册表 upsert 去重，列表不出现重复行（Task 3 测试）。
2. **断线判定**：对方断开连接后设备应标记为离线（灰显），而不是从列表消失或永远在线（Task 5 测试）。
3. **ALPN 不一致**：mDNS 会广播发现局域网内**所有** iroh 端点（含其他应用），连接时须用 ALPN `onelink-v1` 过滤，非 OneLink 端点连接失败且不进入设备列表（Task 4/5 测试）。
4. **退出清理**：应用退出时 tokio runtime 与 iroh endpoint 优雅关闭，不 panic、不残留线程（Task 7 验证）。
5. **事件积压**：网络事件风暴（大量设备/频繁上下线）时 UI 事件队列有界、旧事件被丢弃而非阻塞或崩溃（Task 4 测试）。

- [ ] **Step 3: 实现 `src/net.rs`**

要点：
- `spawn_iroh_service`：`std::thread::spawn` 内建 tokio `Runtime`；`Endpoint::bind(presets::N0)`（presets::N0 默认启用官方 relay + DNS 查找，符合方案 relay 决策）→ `let mdns = MdnsAddressLookup::builder().build(endpoint.id())?` → `endpoint.address_lookup()?.add(mdns.clone())`
- 事件循环：`tokio::spawn` 两个任务——(a) `mdns.subscribe()` 流：discovered/expired 事件经 `translate_mdns_event` 转 `UiEvent` 后 `tx.try_send`（满即丢，不阻塞）；(b) `endpoint.accept()` 循环：accept 到的连接先校验 ALPN（非 `onelink-v1` 直接 `conn.close` 拒绝），M1 仅记录日志（握手在 Task 5 接入）
- 本机 `node_id = endpoint.id().to_string()`
- 事件循环里出现错误 → `UiEvent::NetError` 继续跑，不退出线程
- `translate_mdns_event` 的参数用内部 trait `MdnsEventLike` 统一，真实 mDNS 事件在桥接处适配
